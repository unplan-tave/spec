# Feature Specification: 카드리스트 (목록 · 필터 · 검색)

**Feature Branch**: `005-card-list`

**Created**: 2026-11-24

**Status**: Draft

**Input**: 원본 기능명세서 R118~R143, IA R25~R30

**관련 화면**: `CARD-LIST`, `CARD-SEARCH`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전체 카드 훑어보기 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 카드가 있는 사용자, **When** GNB 카드리스트를 누르면, **Then** 모든 카드가 월별(`YYYY. MM`, 최신 월이 위)로 묶여 표시되고 상단에 "총 n개의 카드"가 보인다.
2. **Given** 목록의 핀 카드, **When** 보면, **Then** 제목, 시작일~종료일(같은 날이면 한 번만), 시작~종료 시각, 컨디션 태그, 개인 태그(최대 1~2개)가 보인다.
3. **Given** 목록의 큐 카드, **When** 보면, **Then** 제목, 마감일 `~MM/DD`, "약 N시간 M분 소요", 태그가 보이며 배경이 핀 카드보다 투명하다.
4. **Given** 진행도가 완료인 카드, **When** 보면, **Then** 제목에 취소선이 있다.
5. **Given** 카드가 하나도 없음, **When** 들어오면, **Then** 빈 목록 상태가 보인다.

---

### User Story 2 - 필터로 좁히기 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** `CARD-LIST`, **When** 카드 유형 칩에서 큐 카드를 고르면, **Then** 큐 카드만 보이고 총 개수가 다시 계산된다.
2. **Given** 카드 유형 = 핀, 컨디션 태그 = 핵심 작업 필터 적용, **When** 목록을 보면, **Then** 두 조건을 모두 만족하는 카드만 보인다.
3. **Given** 만든 개인 태그가 없음, **When** 개인 태그 칩을 열면, **Then** 드롭다운에 항목이 없다.

---

### User Story 3 - 제목으로 검색 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** `CARD-LIST`, **When** 검색바("일정 카드 검색")를 누르면, **Then** `CARD-SEARCH`가 열리고 최근 검색어가 보인다 (없으면 "최근 검색 내역이 없습니다").
2. **Given** `CARD-SEARCH`, **When** 공백이 아닌 1자 이상을 입력하고 엔터를 누르면, **Then** 제목에 검색어가 포함된 카드가 표시되고 일치 부분이 파란색으로 강조된다.
3. **Given** 결과 없음, **When** 검색하면, **Then** 검색 결과 없음 상태가 보인다.

---

### Edge Cases

- 필터와 검색을 동시에 적용할 수 있는가 (검색 결과에도 필터 칩이 있는가): [NEEDS CLARIFICATION: Q-074]
- 기간 일정이 두 달에 걸칠 때 → 핀 카드는 **시작일** 기준 월에 묶인다. (R139)
- 큐 카드 소요 시간이 미정이면 목록 표시: [NEEDS CLARIFICATION: Q-075 "시간 미정" 표시 제안]

## Requirements *(mandatory)*

### Functional Requirements

**목록**

- **FR-LIST-001**: GNB 카드리스트 탭은 모든 카드를 기본 정렬·필터 상태로 표시해야 한다. 카드가 없으면 빈 상태. (R118, R119)
- **FR-LIST-002**: 카드를 날짜 기준 월로 묶고 월은 내림차순으로 정렬한다. 기준 날짜: 핀 카드 = 시작일, 큐 카드 = 마감일. 월 표기 `YYYY. MM`. (R139) [NEEDS CLARIFICATION: Q-032 같은 월 안의 정렬]
- **FR-LIST-003**: 현재 보이는 카드 수를 "총 n개의 카드"로 표시하고 조건이 바뀔 때마다 갱신한다. (R138)
- **FR-LIST-004**: 핀 카드 항목: 제목, 시작일·종료일(같은 날이면 1번), 시작~종료 시각, 컨디션 태그, 개인 태그 최대 1~2개(글자 수 기준). (R140) [NEEDS CLARIFICATION: Q-050]
- **FR-LIST-005**: 큐 카드 항목: 제목, 마감일 `~MM/DD`, "약 N시간 M분 소요", 컨디션·개인 태그, 핀 카드보다 투명한 배경. (R141)
- **FR-LIST-006**: 진행도 완료 카드는 제목에 취소선을 표시한다. (R142)
- **FR-LIST-007**: 카드를 누르면 해당 카드 상세(004)로 이동한다. (R143)

**필터**

- **FR-LIST-010**: 필터 칩 4종을 제공한다: 카드 유형, 진행도, 컨디션 태그, 개인 태그. (R129~R136)
- **FR-LIST-011**: 각 칩은 드롭다운에서 **하나 이상** 복수 선택한다. 같은 칩 안의 여러 값은 OR, 서로 다른 칩끼리는 AND로 결합한다. (R137) — 원본은 "복수 필터 적용"만 명시, 결합 방식은 제안 [NEEDS CLARIFICATION: Q-076]
- **FR-LIST-012**: 카드 유형 값: 전체 카드, 핀 카드, 큐 카드. "전체 카드"와 다른 값을 함께 고를 때의 동작: [NEEDS CLARIFICATION: Q-076] (R130)
- **FR-LIST-013**: 진행도 값은 glossary의 진행도 3단계를 사용한다. (R132) [NEEDS CLARIFICATION: Q-004]
- **FR-LIST-014**: 컨디션 태그 값은 glossary의 6개. (R134)
- **FR-LIST-015**: 개인 태그 칩은 사용자의 개인 태그를 나열하고, 없으면 항목을 표시하지 않는다. (R136)
- **FR-LIST-016**: 필터 결과가 없으면 빈 목록 상태를 표시한다. (R130~R137)
- **FR-LIST-017**: 필터 상태를 화면을 떠났다가 돌아와도 유지하는가: [NEEDS CLARIFICATION: Q-077]
- **FR-LIST-018**: 다른 화면에서 필터를 지정해 진입할 수 있어야 한다 (예: `ADD-SHEET`의 "전체 큐 카드 보기" → 카드 유형 = 큐 카드). (R176)

**검색** (`CARD-SEARCH`)

- **FR-LIST-020**: 검색바를 누르면 검색 화면으로 이동한다. 뒤로 가기는 `CARD-LIST`로 돌아간다. (R120~R123)
- **FR-LIST-021**: 공백을 제외하고 1자 이상일 때만 엔터(검색)를 활성화한다. (R124)
- **FR-LIST-022**: 카드 제목에 검색어가 포함된 카드를 표시하고, 일치 부분을 파란색으로 강조한다. 결과가 없으면 결과 없음 상태. (R125) [NEEDS CLARIFICATION: Q-032 대소문자·공백 처리]
- **FR-LIST-023**: 최근 검색어 목록을 표시하고, 항목별 X로 개별 삭제, "전체 삭제"로 일괄 삭제한다. 비면 "최근 검색 내역이 없습니다". (R126~R128) [NEEDS CLARIFICATION: Q-032 최대 개수·저장 위치·저장 시점]

## Success Criteria *(mandatory)*

- **SC-LIST-001**: 어떤 필터 조합에서도 "총 n개의 카드"와 실제 보이는 카드 수가 같다.
