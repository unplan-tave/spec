# 공통 정책 (Policies)

> 여러 기능에 걸쳐 적용되는 규칙. 각 spec의 요구사항은 여기 정책을 `POL-###`으로 참조한다.
> 상태: `Approved`(원본 시트에서 확정) / `Proposed`(이번 이관 시 새로 제안, 승인 필요)

---

## POL-001 GNB 노출 정책 — `Approved` (원본: 공통 정책 시트)

1. **기본 노출 대상**: 주요 메뉴의 메인 화면에서 GNB를 노출한다.
   - 홈 (Daily / Weekly / Monthly View 모두)
   - 카드리스트
   - 컨디션
   - 설정
2. **미노출 대상**: GNB로 진입하더라도 전체 화면을 차지하는 독립 화면이면 GNB를 숨긴다.
   - 일정 추가 화면 ⚠️ 어느 화면을 말하는지 미확정 (Q-002)
   - 알림 페이지 (`NOTI-LIST`)
   - 그 밖에 화면 맵에서 `GNB: 숨김`으로 정의된 화면
3. **하위 화면 전환**: GNB 미노출 하위 화면으로 이동하면 숨기고, 뒤로 가기로 노출 대상 화면에 돌아오면 다시 표시한다.
4. **오버레이 예외**: 모달, 바텀시트 등 오버레이는 각 UI의 형태와 동작에 따라 결정한다. 오버레이라는 이유만으로 숨기거나 유지하지 않는다.
   - ⚠️ 각 바텀시트·모달의 GNB 노출 여부는 화면 맵의 `GNB` 열에 개별 정의해야 한다. (Q-002)
5. **화면별 예외**: 화면별 명세에 따로 정의된 경우 그 명세를 따른다.

## POL-002 토스트 바 공통 정책 — `Proposed`

원본에 토스트가 7종 있고, 각각 "3초 후 자동 종료, X 버튼으로 즉시 닫기"를 반복 정의하고 있어 공통화한다.

1. 토스트는 표시 후 **3초** 뒤 자동으로 사라진다.
2. 닫기 버튼(X 또는 확인)을 누르면 즉시 사라진다.
3. **행동 버튼이 있는 토스트**(예: "다음날 종료되는 일정으로 등록할까요? [완료]")의 자동 종료 여부: ⚠️ 미확정 (Q-041)
4. 새 토스트가 뜰 때 기존 토스트는 즉시 교체한다. (제안)
5. 토스트 목록과 문구는 각 spec의 `UI Notes`에 정의한다.

## POL-003 바텀시트 헤더 취소/완료 정책 — `Proposed`

원본의 모든 편집용 바텀시트(태그, 날짜/시간, 위치, 마감일/소요시간, 날짜별 메모)가 같은 규칙을 반복한다.

1. **취소**: 바텀시트에서 바꾼 내용을 모두 버리고 닫는다. 바텀시트를 열기 전 상태로 돌아간다.
2. **완료**: 바꾼 내용을 호출한 화면에 반영하고 닫는다.
3. 완료 버튼 활성화 조건은 각 바텀시트 요구사항에 정의한다. 정의가 없으면 항상 활성.
4. 바깥 영역 탭, 아래로 스와이프로 닫는 경우: ⚠️ 취소와 같게 처리할지 미확정 (Q-052). 제안: 취소와 동일.

## POL-004 날짜·시간 표기 정책 — `Proposed`

원본에 흩어진 표기 형식을 모은다.

| 용도 | 형식 | 예시 | 원본 |
|---|---|---|---|
| 홈·컨디션 기준 날짜 | `YYYY.MM.DD.요일` | 2026.11.24.화 | R86, R266 |
| 큐 카드 마감일 (편집) | `YYYY.MM.DD` + D-day | 2026.12.24 D-30 | R244 |
| 큐 카드 마감일 (목록) | `~MM/DD` | ~12/24 | R141 |
| 카드리스트 월 그룹 | `YYYY. MM` | 2026. 04 | R139 |
| 시각 | `HH:MM` (24시간제) | 13:38 | R314 |
| 소요 시간 | `약 N시간 M분 소요` | 약 12시간 30분 소요 | R141 |
| 수면 시간 | `N시간 M분` | 2시간 40분 | R314 |
| D-day | 마감일 당일 `D-0`, 이후 ⚠️ 미확정 (Q-046) | | R245 |

- 주의 시작은 **일요일**, 끝은 토요일이다. (R76, R82)
- 기준 시간대: ⚠️ 미확정 (Q-042). 제안: 기기 시간대 기준, 서버는 UTC 저장.

## POL-005 텍스트 입력 검증 정책 — `Proposed`

1. 글자 수는 앞뒤 공백을 제거(trim)한 뒤 센다. 공백만 입력한 값은 빈 값으로 본다.
2. 글자 수 단위: ⚠️ 이모지·결합 문자를 1자로 볼지 미확정 (Q-053). 제안: 사용자에게 보이는 글자(grapheme) 1개 = 1자.
3. 같은 제한은 FE와 BE가 모두 검사한다. BE 검증 실패 시 FE는 POL-006을 따른다.

| 항목 | 제한 | 원본 |
|---|---|---|
| 날짜별 메모 | 1~20자 | R96~R103 |
| 카드 메모 | 0~2,000자 | R232 |
| 개인 태그 이름 | 1~25자, 계정당 최대 100개 | R199 |
| 카드 검색어 | 공백 제외 1자 이상 | R124 |
| 일정 제목 | 1자 이상, 최대 ⚠️ 미확정 (Q-054) | R184 |
| 회복 방법 직접 입력 | ⚠️ 미확정 (Q-014) | R28 |

## POL-006 오류 안내 공통 정책 — `Proposed`

원본의 "실패 및 예외 처리" 열에 "오류 안내를 표시한다", "실패를 안내한다"가 수십 번 나오지만 형태가 정의되지 않았다.

1. 저장/삭제 실패: 입력값과 기존 데이터를 그대로 유지하고 오류 토스트를 표시한다. (POL-002)
2. 조회 실패: 화면은 빈 상태/기본 상태로 표시하고 재시도 수단을 제공한다. ⚠️ 형태 미확정 (Q-055)
3. 네트워크 없음: ⚠️ 오프라인 동작 미확정 (Q-043)
4. 오류 문구는 디자인이 `UI Notes`에 정의한다.
